# SUPER MASHIO

Браузерный 2D-платформер: бегаешь, прыгаешь, собираешь кошачий корм, в конце уровня
кормишь кошку. Главный герой собран из четырёх фотографий, всё остальное — векторная
мультяшная графика.

Стек: Vite + Phaser 3 (Arcade Physics) + TypeScript. Бэкенда нет, прогресс в localStorage.

---

## Быстрый старт

```bash
npm install
npm run dev
```

Игра — на `http://localhost:5173/`, стенд персонажа — на
`http://localhost:5173/test-player.html`.

Управление: <kbd>←</kbd><kbd>→</kbd> или <kbd>A</kbd><kbd>D</kbd> — бег,
<kbd>Space</kbd> — прыжок (второе нажатие в воздухе — двойной),
<kbd>Shift</kbd> — рывок, <kbd>Esc</kbd> — пауза.
На телефоне появляются джойстик и кнопки; на компьютере их можно вызвать
адресом `?touch=1`.

Если `npm` не находится — открой новый терминал: Node ставился в текущей сессии,
и PATH подхватывается только новыми окнами. Node лежит в `C:\Program Files\nodejs`.

### Что нужно установлено

- **Node.js 18+** — `winget install OpenJS.NodeJS.LTS`
- **Python 3.10+** с библиотеками — только для пересборки кадров игрока:
  ```bash
  python -m pip install pillow numpy scipy
  ```

## Кадры персонажа

### Как переснять

1. Сними себя на белом фоне: `1.png` — стоишь, `2.png` — первый шаг,
   `3.png` — второй шаг, `4.png` — прыжок.
2. Положи их в корень проекта (рядом с `package.json`).
3. Выполни:
   ```bash
   npm run photos
   ```

Скрипт сам скопирует свежие файлы в `photos/`, вырежет фон, выровняет кадры,
нормализует масштаб и цвет, наложит обводку и соберёт
`public/assets/player/player.png` + `player.json`.

Заодно он кладёт рядом `player-debug.png` — контрольный лист: все кадры
по отдельности и друг поверх друга, с линиями пола, центра и таза.
Первым делом смотри именно его.

Фотографий может не быть — тогда соберутся плейсхолдеры и игра всё равно запустится.

### Как добавить новый кадр (падение, победная поза...)

1. Положи фото в корень, например `5.png`.
2. В `scripts/photo-config.json` добавь строку в `frames`:
   ```json
   { "name": "fall", "file": "05.png", "alignBy": "pelvis", "scale": 1.0, "offsetX": 0, "offsetY": 0 }
   ```
3. В `src/entities/PlayerAnimations.ts` добавь кадр в `PLAYER_FRAMES` и подставь
   его в нужную анимацию в `PLAYER_ANIMS`.
4. `npm run photos`.

### Как отладить выравнивание

Открой `test-player.html` — это отдельный стенд, где персонаж просто ходит,
прыгает и делает рывок на пустом фоне.

- <kbd>←</kbd><kbd>→</kbd> / <kbd>A</kbd><kbd>D</kbd> — бег, <kbd>Space</kbd> — прыжок
  (второе нажатие — двойной), <kbd>Shift</kbd> — рывок.
- Галка **сам ходит** — персонаж ходит туда-сюда сам, руки свободны, смотри на цикл.
- Галка **луковица** — все кадры друг на друге справа: сразу видно, какой разъезжается.
- Ползунки **подвижки кадров** двигают конкретный кадр в пикселях исходника.
  Поймал нужное — жми **Собрать offsets для photo-config.json**, вставь выданный
  блок `frames` в `scripts/photo-config.json` и запусти `npm run photos`.

Так подвижка становится постоянной: она вшивается в сам спрайтшит,
а ползунки возвращаются в ноль.

### Что крутится в `scripts/photo-config.json`

| Ключ | Что делает |
|---|---|
| `canvas` | размер кадра в атласе |
| `anchor.x` / `anchor.floorY` | куда ставится центр таза и линия пола внутри кадра |
| `figureHeight` | рост фигуры в пикселях; общий масштаб считается по нему |
| `pelvisBand` | какая полоса силуэта считается тазом (доли роста сверху вниз) |
| `frames[].alignBy` | `floor` — ставим на пол, `pelvis` — совмещаем таз с эталонным кадром |
| `frames[].offsetX/Y` | ручная доводка кадра |
| `key.*` | вырезание фона: порог белого, допуск по цвету, обжатие и размытие края |
| `style.*` | насыщенность, яркость, контраст, подъём теней, постеризация, обводка |

Два места, где легко ошибиться, и почему сделано именно так:

- **Кадр прыжка нельзя ставить на пол** — ноги в воздухе. Поэтому у него
  `alignBy: "pelvis"`: он совмещается по тазу с кадром стойки.
- **Масштаб общий на все кадры.** Фото сняты с одной точки, значит относительные
  размеры уже верные. Нормализация по высоте силуэта раздула бы кадр прыжка,
  где ноги поджаты.

## Уровни

Уровни — данные, а не код: `src/levels/level1.json`. Поправил числа, обновил
страницу — уровень другой. Формат описан в `src/levels/types.ts`.

```jsonc
{
  "name": "Двор", "catName": "Ахчи", "palette": "yard",
  "width": 5400, "spawn": { "x": 160, "y": 620 }, "finish": { "x": 5060, "y": 620 },
  "platforms": [ { "x": 0, "y": 620, "w": 900, "h": 140 } ],   // y — верх площадки
  "pickups":   [ { "type": "dry", "x": 320, "y": 560, "count": 5, "stepX": 62 } ],
  "hazards":   [ { "type": "vacuum", "x": 2650, "y": 620, "from": 2560, "to": 3120 } ],
  "decor":     [ { "kind": "tree", "x": 470, "y": 620, "scale": 1.2 } ],
  "stars": [45, 80, 110]                                        // пороги на 1/2/3 звезды
}
```

- **Корм:** `dry` — 1 очко, `pouch` — 5, `can` — 10, `fish` — 25.
  `count` + `stepX/stepY` делают дорожку, `arc` выгибает её дугой над ямой.
- **Опасности:** `puddle`, `vacuum`, `yarn`, `icicle`. Урона по здоровью нет:
  теряешь часть корма и отлетаешь. Цены — в `HAZARD_COST` в `src/entities/Hazard.ts`.
- **Декор:** `bush`, `tree`, `fence`, `lamp`, `box`, `flowers` — рисуется процедурно
  под палитру уровня в `src/systems/Textures.ts`.
- **Ямы:** одиночный прыжок берёт около 190 px по горизонтали, двойной — примерно
  вдвое больше. Ямы шире 200 px без платформ лучше не делать.

Новый уровень: положить `level2.json` рядом и дописать одну строку
в `src/levels/index.ts`. Палитры уровней — в `src/config/palettes.ts`.

## Финал уровня

Хореография кормления лежит отдельно, в `src/systems/Finale.ts`, и читается
сверху вниз: камера подъезжает → кошка замечает и мяукает → бежит навстречу →
трётся о ногу → игрок подходит к миске и высыпает корм (счётчик утекает в ноль,
крокеты сыплются частицами) → кошка ест → садится, умывается, летят сердечки.
Правится там же, геймплей при этом не трогается.

Сама кошка — `src/entities/Cat.ts`: векторная, собрана из частей
(корпус, голова с ушами, четыре лапы, хвост из трёх сегментов).
Походка и хвост считаются процедурно, разовые движения — твинами.

Две вещи, на которых легко обжечься при правке кошки:
- SVG грузятся в **двойном** размере ради чёткости и рисуются с `SVG_SCALE = 0.5`.
  Любой твин, который трогает `scale`, обязан считать от `SVG_SCALE`, иначе часть
  внезапно раздувается вдвое.
- Сегменты хвоста смещаются на величину **меньше** длины предыдущего сегмента,
  иначе хвост распадается на отдельные палки.

## Физика и ощущения

Все коэффициенты — в `src/config/tuning.ts`, одним файлом:
скорость, разгон, гравитация, высота прыжка, двойной прыжок, coyote time,
jump buffering, рывок, squash & stretch, дыхание, тень.

Хитбокс (`TUNING.hitbox`) задаётся прямоугольником в мировых пикселях
и живёт отдельно от размера спрайта: фото по краям всегда шире реальной фигуры.

Устроено так: настоящий персонаж для физики — невидимый прямоугольник, а фото-спрайт
просто следует за ним. Поэтому растяжения, наклоны и подвижка кадров никак не трогают
столкновения.

## Звук

Готовых сэмплов в проекте нет — всё синтезируется через Web Audio
в `src/systems/AudioManager.ts`: прыжок, сбор, приземление, рывок, удар, мяу,
мурчание, сыплющийся корм и фоновая мелодия. Браузер не даёт включить звук
до первого действия пользователя, поэтому `unlock()` вызывается по первому
клику или нажатию клавиши. Кнопка динамика в HUD выключает звук, выбор
запоминается в localStorage.
